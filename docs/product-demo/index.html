Why a compiler?

A file that opens is not a document you can trust.

Word will render almost anything. A document compiler makes the requirements explicit, checks them in one pass, and refuses to render a document that breaks its contract.

01 / AUTHOR

Keep the source readable

Draft in Markdown: ordinary paragraphs, headings and lists, with YAML for the facts that belong in a letter.

02 / VERIFY

Make requirements checkable

A schema declares the fields, structure and rules. docc points at every issue with a source location and a useful hint.

03 / BUILD

Keep layout out of prose

A theme owns the stationery, styles and furniture. A valid source builds to a deterministic .docx with that chosen layout.

The whole system

One small pipeline. Clear responsibility at every step.

01 / SOURCEMarkdownReadable prose and frontmatter, in one diffable file.
02 / PARSEStructureHeadings, blocks, spans and fields are understood as document parts.
03 / VERIFYSchemaRequired facts, ordering and document-specific rules are checked together.
04 / EMITTheme → .docxValidated content meets fixed layout, with repeatable output.
The important boundary: docc does not invent content, operate a template editor or hide your prose in a database. It compiles an authored document and gates rendering on validation.
