# docc marketplace (experimental)

For a Claude plugin marketplace, use the repository root: it declares one in
`.claude-plugin/marketplace.json` and installs the portable skill from
`skills/docc`. See [Publishing the Agent
Skill](../../docs/publishing-agent-skill.md).

This directory remains an **experimental prototype** around the Cowork skill in
`cowork/docc`, not a supported distribution channel. The supported delivery
artifact here is the ZIP generated by `sh cowork/assemble.sh` at
`cowork/docc-cowork-skill.zip`.

Plugin support is beta. The generated skill payload is deliberately ignored by
git, so this checked-out directory cannot be installed as a marketplace without
first running `assemble.sh`. Do not direct users here for production delivery.

## Layout

```
marketplace/
├── marketplace.json                     # lists the plugins + their sources
└── plugins/
    └── docc/
        ├── .claude-plugin/plugin.json   # plugin manifest (name, version, …)
        └── skills/
            └── docc/                     # the skill payload (SKILL.md, bin/, config/, …)
```

The `skills/docc/` payload is **generated** from the canonical skill at
`cowork/docc/` by `cowork/assemble.sh`. Edit the skill there, then
re-run assemble — never hand-edit the copy under `marketplace/`.

## Prototype workflow

To exercise the prototype locally, edit the canonical skill in `cowork/docc/`,
then run `sh cowork/assemble.sh` to create the ignored payload. Keep the two
manifest versions aligned when testing version handling. This workflow does not
publish or update a production installation.

## Future distribution work

Before this can become a supported channel, choose one of these payload models:

- **Commit the binary** (consider Git LFS to keep history lean), or
- **Switch the source** in `marketplace.json` to a hosted archive and let Claude
  fetch it at install time — no binary in git:

  ```json
  "source": { "type": "archive",
              "url": "https://.../docc-cowork-skill-<version>.zip",
              "sha256": "<hash>" }
  ```

  (`github` and `git-subdir` source types are also available.)

For a public marketplace, prefer a hosted archive with a pinned `sha256`.
Until then, build and distribute the standalone ZIP.
